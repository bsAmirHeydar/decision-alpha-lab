# استاندارد اعتبارسنجی قبل از فروش

هدف اعتبارسنجی این نیست که محصول را بی‌نقص نشان بدهد؛ هدف این است که بدانیم محصول در چه شرایطی مفید، بی‌اثر یا گمراه‌کننده است.

## حداقل تست‌ها

| تست | هدف |
|---|---|
| بازار رونددار | آیا ابزار در حرکت‌های تمیز شلوغ نمی‌شود؟ |
| بازار رنج | آیا هشدارهای بی‌ارزش زیاد تولید نمی‌کند؟ |
| خبر و اسپایک | آیا رفتار افراطی قابل کنترل است؟ |
| تایم‌فریم پایین | آیا سرعت و لیبل‌ها قابل تحمل هستند؟ |
| تایم‌فریم بالا | آیا ساختار دیر یا ناقص تشخیص داده نمی‌شود؟ |
| دیتای کم | آیا اندیکاتور خطای واضح و تمیز می‌دهد؟ |

## معیارهای مشاهده

برای هر محصول باید این موارد ثبت شود:

- تعداد سیگنال/آبجکت در بازه تست
- تعداد موارد واضح و خوانا
- تعداد موارد شلوغ یا مبهم
- تعداد خطاهای بصری
- تعداد خطاهای محاسباتی
- کندی یا فشار روی چارت
- کیفیت تجربه کاربر

## خروجی اعتبارسنجی

هر تست باید با این قالب ذخیره شود:

```text
Product:
Version:
Symbol:
Timeframe:
Period:
Market Regime:
Observed Strength:
Observed Weakness:
Screenshots:
Decision:
```

## تصمیم نهایی

محصول فقط وقتی وارد Beta می‌شود که:

1. کرش یا خطای کامپایل نداشته باشد.
2. در سناریوهای پایه رفتار قابل توضیح داشته باشد.
3. راهنمای مشتری با واقعیت ابزار یکی باشد.
4. محدودیت‌ها پنهان نشده باشند.
5. حداقل یک نمونه استفاده واقعی مستند شده باشد.
