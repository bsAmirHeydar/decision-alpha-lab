# استاندارد طراحی اندیکاتور قابل فروش

این سند چک‌لیست طراحی هر اندیکاتور است.

## 1. نام و جایگاه

هر اندیکاتور باید نام محصولی، نام داخلی و نقش مشخص داشته باشد.

| فیلد | نمونه |
|---|---|
| Product Name | NDS Lens Pro |
| Internal Slug | nds-lens-pro |
| Category | Decision Lens |
| Platform | MetaTrader 5 |
| Audience | Intraday discretionary traders |

## 2. خروجی بصری

قبل از کدنویسی نهایی باید مشخص شود:

- چه چیزی روی چارت رسم می‌شود؟
- رنگ‌ها چه معنایی دارند؟
- لیبل‌ها چطور خوانده می‌شوند؟
- در تایم‌فریم‌های مختلف شلوغی چطور کنترل می‌شود؟
- اگر دیتا کم بود یا ساختار ناقص بود، اندیکاتور چه رفتاری دارد؟

## 3. Inputهای محصولی

Inputها باید برای مشتری ساده باشند. ورودی‌های مهندسی و پیچیده باید یا مخفی شوند یا در حالت Advanced قرار بگیرند.

### الگوی پیشنهادی Input

| گروه | مثال |
|---|---|
| Display | Show Labels, Show Zones, Theme |
| Detection | Sensitivity, Strict Mode, Lookback |
| Alerts | Enable Alerts, Alert On Close, Push Notification |
| Performance | Max Bars, Refresh Mode |
| License | License Key, User ID |

## 4. اصل تمیزی چارت

اندیکاتور فروشی باید از ابتدا برای خوانایی ساخته شود:

- لیبل‌ها روی هم نیفتند.
- رنگ‌ها محدود و معنادار باشند.
- حالت خاموش/روشن برای هر لایه وجود داشته باشد.
- تایم‌فریم عوض شد، آبجکت‌های قبلی کنترل شوند.
- نسخه، نام و واترمارک مزاحم چارت نباشد.

## 5. خطایابی محصولی

هر اندیکاتور باید یک حالت Debug داخلی داشته باشد، اما پیش‌فرض آن خاموش باشد. خروجی خطایابی باید به درد توسعه و پشتیبانی بخورد، نه مشتری عادی.

## 6. مرز محصول با استراتژی

اندیکاتور می‌تواند دید بدهد، اما نباید بدون طراحی جداگانه تبدیل به وعده معامله قطعی شود. هر محصول باید بخش «این ابزار چه کاری نمی‌کند» داشته باشد.
