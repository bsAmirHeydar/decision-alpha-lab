# استاندارد بسته‌بندی و انتشار

این سند مشخص می‌کند خروجی قابل فروش چگونه آماده شود.

## محتویات پکیج انتشار

هر نسخه آماده فروش باید حداقل این ساختار را داشته باشد:

```text
release-package/
├── indicator-or-tool-file
├── USER_GUIDE.pdf یا USER_GUIDE.md
├── INSTALL.md
├── CHANGELOG.md
├── LICENSE_NOTES.md
├── screenshots/
└── version.txt
```

## نام‌گذاری نسخه‌ها

الگوی پیشنهادی:

```text
<ProductSlug>_v<Major>.<Minor>.<Patch>_<Platform>.zip
```

نمونه:

```text
nds-lens-pro_v1.0.0_mt5.zip
```

## نسخه‌بندی

| نوع تغییر | نسخه |
|---|---|
| تغییر کوچک، اصلاح متن یا ظاهر | Patch |
| قابلیت جدید بدون شکستن رفتار قبلی | Minor |
| تغییر جدی در منطق یا ناسازگاری با قبل | Major |

## کانال‌های انتشار

- فروش مستقیم با فایل لایسنس‌دار
- اشتراک ماهانه با فعال‌سازی دستی یا نیمه‌خودکار
- انتشار نسخه Beta برای گروه محدود
- نسخه رایگان سبک برای جذب لید
- نسخه Pro با لایه‌های بیشتر، هشدار و پشتیبانی

## چک‌لیست قبل از ارسال به مشتری

- فایل صحیح و آخرین نسخه است.
- نام محصول و نسخه داخل فایل‌ها یکسان است.
- راهنمای نصب با ساختار فایل هماهنگ است.
- لایسنس یا محدودیت استفاده تست شده است.
- اسکرین‌شات‌های راهنما با UI فعلی یکی است.
- پیام‌های خطا برای مشتری قابل فهم هستند.
