# Product Lab — ابزارها و اندیکاتورهای قابل فروش

این پوشه یک لایه مستقل برای تبدیل ایده‌های تحلیلی پروژه به محصول قابل فروش است. هدف آن جدا کردن «تحقیق و آزمایش» از «محصول تجاری، مستند، قابل پشتیبانی و قابل نسخه‌بندی» است.

## فلسفه پوشه

هر ابزار یا اندیکاتور فقط وقتی وارد این بخش می‌شود که بتواند به یکی از این خروجی‌ها برسد:

1. **اندیکاتور فروشی**: فایل قابل نصب برای تریدر، همراه با راهنمای استفاده، لایسنس، نسخه‌بندی و مستند فروش.
2. **ابزار کمکی**: ابزار استخراج، تست، گزارش‌گیری، تولید فایل، آماده‌سازی دیتا یا اتوماسیون فروش/پشتیبانی.
3. **پکیج محصولی**: ترکیب چند اندیکاتور، راهنما، چک‌لیست، قالب ژورنال و مدل اشتراک.

## ساختار اصلی

```text
product_lab/
├── 00_START_HERE.md
├── indicators/          # هر اندیکاتور قابل فروش اینجا یک پوشه مستقل دارد
├── tools/               # ابزارهای غیراندیکاتوری یا ابزارهای پشتیبان فروش/تحقیق
├── docs/                # استانداردها، پلی‌بوک‌ها، چک‌لیست‌ها
├── registry/            # کاتالوگ محصولات، وضعیت‌ها، قیمت، نسخه‌ها
├── backlog/             # ایده‌های خام و صف ساخت
├── releases/            # خروجی‌های آماده انتشار و بسته‌بندی
├── customer_docs/       # متن‌هایی که مستقیماً به مشتری داده می‌شود
├── assets/              # تصویر، اسکرین‌شات، لوگو، نمونه چارت
└── scripts/             # اسکریپت‌های ساخت قالب و مدیریت محصول
```

## اصل تفکیک

- `lab/` برای فرضیه، تست، تحقیق و اعتبارسنجی است.
- `mql5/` برای کد قابل کامپایل و اتصال به متاتریدر است.
- `product_lab/` برای تبدیل خروجی به محصول قابل فروش است.

هیچ اندیکاتور فروشی نباید فقط یک فایل کد باشد. محصول باید همزمان این‌ها را داشته باشد: ایده روشن، کاربرد مشخص، محدودیت شفاف، راهنمای نصب، راهنمای استفاده، سیاست نسخه‌بندی، لاگ تغییرات، برنامه تست، مدل قیمت‌گذاری و مسیر پشتیبانی.

## مسیر استاندارد ساخت محصول

1. ایده خام در `backlog/ideas.md` ثبت می‌شود.
2. برای ایده یک پوشه از قالب ساخته می‌شود.
3. مشخصات محصول در `PRODUCT_SPEC.md` کامل می‌شود.
4. معیارهای تست و اعتبارسنجی در `VALIDATION_PLAN.md` نوشته می‌شود.
5. راهنمای مشتری در `USER_GUIDE.md` جدا از مستند داخلی نوشته می‌شود.
6. وضعیت محصول در `registry/indicator_catalog.md` یا `registry/tool_catalog.md` ثبت می‌شود.
7. خروجی نهایی در `releases/` بسته‌بندی می‌شود.

## ساخت سریع اندیکاتور جدید

از روت پروژه:

```powershell
.\product_lab\scripts\New-ProductLabItem.ps1 -Type indicator -Slug "nds-lens-pro" -Title "NDS Lens Pro"
```

برای ابزار:

```powershell
.\product_lab\scripts\New-ProductLabItem.ps1 -Type tool -Slug "license-console" -Title "License Console"
```
