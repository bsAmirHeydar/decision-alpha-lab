# شروع کار با Product Lab

این فایل نقطه شروع ساخت ابزارها و اندیکاتورهای قابل فروش داخل پروژه است.

## تصمیم معماری

از این لحظه هر چیزی که قرار است محصول شود، باید از فضای تحقیق جدا شود. تحقیق می‌تواند ناقص، خام و در حال تغییر باشد؛ اما محصول باید منظم، قابل توضیح، قابل نصب، قابل فروش و قابل پشتیبانی باشد.

## تعریف محصول قابل فروش

یک اندیکاتور یا ابزار زمانی «محصول» محسوب می‌شود که این هشت شرط را داشته باشد:

| شرط | توضیح |
|---|---|
| مسئله روشن | دقیقاً چه درد یا نیاز تریدر را حل می‌کند؟ |
| خروجی قابل دیدن | کاربر روی چارت یا گزارش دقیقاً چه چیزی می‌بیند؟ |
| قوانین استفاده | چه زمانی استفاده شود و چه زمانی استفاده نشود؟ |
| محدودیت شفاف | چه چیزی را تضمین نمی‌کند؟ |
| تست پایه | حداقل چند سناریوی مارکت روی آن دیده شده باشد. |
| نسخه‌بندی | هر تغییر با نسخه و لاگ تغییرات ثبت شود. |
| بسته نصب | فایل‌ها و مسیر نصب مشخص باشد. |
| سند مشتری | مشتری بدون تماس مستقیم بتواند نصب و استفاده کند. |

## وضعیت‌های محصول

| وضعیت | معنی |
|---|---|
| `idea` | فقط ایده خام است. |
| `spec` | صورت‌مسئله و طراحی محصول نوشته شده. |
| `prototype` | نمونه اولیه ساخته شده اما هنوز قابل فروش نیست. |
| `validation` | در حال تست و مشاهده روی بازار است. |
| `beta` | برای چند کاربر محدود قابل ارسال است. |
| `release` | آماده فروش عمومی است. |
| `deprecated` | دیگر توسعه داده نمی‌شود. |

## قانون طلایی

قبل از نوشتن کد نهایی، اول باید بدانیم کاربر برای چه چیزی پول می‌دهد. اندیکاتور خوب فقط چیزی نیست که روی چارت خط بکشد؛ باید تصمیم، تمرکز یا سرعت تحلیل کاربر را بهتر کند.
