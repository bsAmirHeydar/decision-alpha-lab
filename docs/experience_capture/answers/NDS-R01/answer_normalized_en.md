# NDS-R01 — Normalized Interpretation

## Core Claim

The canonical NDS model is axis-based.

The market must be represented through two primary structural axes:

```text
X-axis = Hook logic = Node-counting
Y-axis = Rally logic = F-counting
```

The same X/Y logic is applied fractally across timeframes.

Higher timeframes dominate lower timeframes.

Symmetry is a native NDS concept and must be represented because it can improve:

```text
entry point precision
zone definition
Extreme entry accuracy
```

## Canonical Axes

### X-Axis

The X-axis represents:

```text
Hook
Node-counting
Hook sequence
Node structure
Hook symmetry
```

The X-axis is not a generic horizontal price axis.

It is a structural axis of Hook and node behavior.

### Y-Axis

The Y-axis represents:

```text
Rally
F-counting
F1 / F2 / F3 structure
Rally expansion
F symmetry
```

The Y-axis is not a generic vertical price axis.

It is a structural axis of Rally and F behavior.

## Deterministic Objects vs Learnable Policy Objects

### Deterministic Anatomy Objects

These are part of NDS anatomy and should not be learned or redefined by AI:

```text
X-axis = Hook / Node-counting
Y-axis = Rally / F-counting
F2 >= F1 rule
Hook 1/2/3 symmetry tendency
Hook 4 extension possibility
fractal application across scales
higher timeframe dominance
node penetration invalidation
Extreme as limit-based local reversal entry
stop behind node for Extreme
```

### Learnable / Policy Objects

These can be learned, ranked, tested, or optimized:

```text
context_power_score
zone_quality_score
destination_openness_score
symmetry_usefulness_score
Extreme width policy
anchor ranking
multi-anchor execution policy
veto policy
cancel/replace policy
win-rate improvement without reward sacrifice
```

## Fractal Model

Fractality means:

```text
the same Hook/node-counting and Rally/F-counting logic is applied across multiple timeframes
```

The system should not create different ontologies for different timeframes.

Instead:

```text
same object model
different scale_id
explicit parent/child relations
```

Parent scale dominance must be represented:

```text
parent_context_dominates_child_context = true
```

But lower timeframe objects can refine entries.

## Symmetry Role

Symmetry is a key NDS-native feature.

It may help with:

```text
entry point precision
zone construction
Extreme accuracy
anchor selection
context quality
```

Symmetry should be stored as both deterministic observation and learnable feature.

Deterministic observation:

```text
F2 >= F1
Hook 1/2/3 often symmetric
Hook 4 can extend beyond symmetry
```

Learnable feature:

```text
Does symmetry improve entry accuracy?
Does symmetry improve reward?
Does symmetry improve Extreme fill quality?
Does symmetry improve zone definition?
```

```text
NDS = {
  X_AXIS: Hook + NodeCounting,
  Y_AXIS: Rally + FCounting,
  FRACTALITY: same logic across scales,
  DOMINANCE: higher timeframe dominates lower timeframe,
  SYMMETRY: native feature for zones/entries/Extreme precision
```

## Short Formal Statement

The canonical NDS object model is built on two structural axes: X-axis as Hook and node-counting, and Y-axis as Rally and F-counting. The same logic is applied fractally across timeframes, with higher timeframes dominating lower ones. Symmetry is an NDS-native object: F2 must be at least equal to or larger than F1; Hooks 1, 2, and 3 often show symmetry; Hook 4 may extend beyond the usual symmetry. These symmetry relations can help define zones, entry points, and more accurate Extreme entries, but their execution value should be tested as learnable policy.
