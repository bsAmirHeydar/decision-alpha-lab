# BASE-02 — Normalized Interpretation

## Core Claim

A scenario is not just a direction.

A scenario is a structured case file.

It starts with a directional thesis, but it becomes a real scenario only when it is connected to context, reasons, approximate entry zone, exact entry logic, invalidation, destination, and fractal relationship.

## Scenario Is a Case File

A scenario should be represented as:

```text
direction
context
reason set
fractal support/conflict
approximate entry zone
exact entry candidate
invalidation logic
destination logic
status
```

The directional thesis alone is not enough.

A bullish or bearish idea can exist before an entry is ready, but it should be classified as an early scenario or directional case, not as a fully executable scenario.

## Direction + Context

Every scenario must be built through the same two-axis framework from BASE-01:

```text
Direction:
  bullish
  bearish

Context:
  Hook
  Rally
```

Therefore, a complete scenario analysis should ask:

```text
What is the bullish Hook case?
What is the bullish Rally case?
What is the bearish Hook case?
What is the bearish Rally case?
```

This means a scenario is not a single conclusion.

It is a structured argument built from the available interpretations.

## Three-Layer Scenario Construction

Amir defined three important layers.

### Layer 1 — Direction

First, decide what directional cases are alive:

```text
bullish case
bearish case
```

This is broad and does not yet require a precise entry.

### Layer 2 — Approximate Entry Zone

Second, identify the approximate structural zone where the scenario could become executable.

This is not the exact price yet.

It is the area where the scenario starts to have a practical trading location.

Examples:

```text
near an unreached L2 node
inside an extreme zone
near a structural invalidation node
inside a higher-timeframe supportive context
```

### Layer 3 — Exact Entry Point

Third, define the exact entry candidate.

This is where the scenario becomes execution-ready.

For example:

```text
limit entry near selected extreme
stop behind the anchor node
destination defined
spread acceptable
execution policy allowed
```

## Fractal Scenario Logic

A scenario must be built fractally.

A lower-scale bearish F3 can be a bullish entry opportunity if the higher-scale context is bullish.

Example structure:

```text
parent scale = bullish
current/lower scale = bearish F3
interpretation = lower-scale bearish exhaustion may create bullish entry
```

This means the system must not treat lower-timeframe direction in isolation.

The lower timeframe can provide:

```text
entry refinement
temporary counter-move
F3 terminal candidate
extreme approach
liquidity/stop location
```

while the higher timeframe can provide:

```text
main scenario direction
destination
continuation energy
veto or support
```

## Scenario Invalidation

Each scenario must have an invalidation derived from the project's market anatomy.

Invalidation is not arbitrary.

It must come from:

```text
X-axis structure
Hook/Rally context
F-counting logic
node validity
fractal context
destination/invalidation geometry
```

A scenario remains alive only while its structural invalidation has not occurred.

## Weak Scenario vs Dead Scenario

Based on the answer, the difference can be formalized as follows.

### Weak Scenario

A weak scenario is still alive, but its reasons are insufficient, conflicted, or not execution-ready.

Possible weak scenario states:

```text
directional thesis exists
entry zone is not clear yet
fractal support is weak
opposite scenario is still strong
destination is not open enough
execution cost is poor
exact entry is not ready
```

### Dead Scenario

A dead scenario is structurally invalidated.

Possible dead scenario states:

```text
invalidation node hit/broken
Hook/Rally interpretation invalidated
F-counting premise failed
parent context overrode it
destination disappeared
entry zone lost structural meaning
selected extreme no longer valid
```

## Can a Scenario Be Alive Without Entry?

Yes.

A scenario can be alive without an exact entry.

However, it must be classified correctly.

Suggested status states:

```text
DIRECTIONAL_CASE_ONLY
ZONE_CANDIDATE
ENTRY_CANDIDATE
EXECUTION_READY
WEAK_ALIVE
INVALIDATED_DEAD
```

A directional thesis can be alive before entry exists.

But it should not be executable until the approximate zone and exact entry logic are defined.

## AI Relevance

This answer defines the future scenario dataset.

AI should not receive only a binary direction.

AI should receive complete scenario objects.

Each scenario object should include:

```text
direction
Hook/Rally basis
reason vector
fractal relation
entry zone
entry candidate
invalidation
destination
status
quality score
execution readiness
```

AI can then:

```text
rank scenarios
compare bullish vs bearish cases
detect weak but alive scenarios
detect dead scenarios
delay execution
veto invalidated scenarios
select execution templates
```

## Short Formal Statement

A scenario is a structured, multi-layer case file that begins with direction, is justified through Hook/Rally and fractal reasons, becomes practical through an approximate entry zone, becomes executable through an exact entry point, and remains alive only while its anatomy-based invalidation has not occurred.
