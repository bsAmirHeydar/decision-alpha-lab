# EXT-10 — Normalized Interpretation

## Core Claim

A good Extreme is not defined by the entry point alone.

A deceptive Extreme is not detected by looking only at the node.

The quality of an Extreme comes from:

```text
context quality
zone quality
potential quality
reward exposure
scenario validity
```

Therefore, the Veto Model must not be an isolated anchor-node model.

It must be a context-zone-entry veto model.

## Extreme Alone Is Not Enough

An Extreme can look attractive because:

```text
price is near a node
risk looks narrow
stop can be placed behind the node
reward may look large
```

But that does not automatically make it a good trade.

The Extreme is only the entry point.

The deeper question is:

```text
Is this Extreme inside the correct NDS context and the correct potential zone?
```

If the answer is no, then the Extreme can be deceptive.

## Good Extreme

A good Extreme is an Extreme that appears after the higher-level NDS process has already produced:

```text
valid context
valid scenario
valid trading zone
valid direction or optionality
clear invalidation
open reward path
positive expectancy potential
```

The entry itself can be very small and fragile, but that is acceptable if the surrounding context and zone make the reward potential meaningful.

## Deceptive Extreme

A deceptive Extreme is an Extreme-like entry that exists near a node but does not belong to a valid context or zone.

Examples of deceptive Extreme conditions:

```text
node is present but the context is weak
node is present but the zone is not a valid trading region
entry is narrow but reward path is not open
risk is small but the scenario is not alive
local Extreme exists but parent context does not support the trade
entry looks precise but potential is low
```

The deception comes from confusing entry precision with opportunity quality.

## Warning Before Entry

The warning is not necessarily a candle signal or an indicator signal.

The warning is structural:

```text
context not strong enough
zone not correct
reward not large enough
destination not open
scenario not valid
parent context not supportive
entry exists before the system has made a valid direction/region decision
```

This means the warning should be generated by upstream NDS layers, not by external technical tools.

## Veto Model Implication

The future Veto Model should not ask only:

```text
is price near an Extreme anchor?
```

It should ask:

```text
is the context valid?
is the zone valid?
is the scenario alive?
is reward exposure sufficient?
is this entry requested by a higher-level scenario?
is the Extreme only a local attraction without real potential?
```

Suggested model name:

```text
Context-Zone Extreme Veto Model
```

## Negative Example Definition

The project needs to label negative examples where:

```text
Extreme geometry existed
but context/zone did not justify entry
```

These examples are critical because they teach the system not to overtrade every narrow-risk node.

Possible labels:

```text
EXTREME_GEOMETRY_PRESENT_CONTEXT_INVALID
EXTREME_GEOMETRY_PRESENT_ZONE_INVALID
EXTREME_GEOMETRY_PRESENT_LOW_POTENTIAL
EXTREME_GEOMETRY_PRESENT_NO_REWARD_PATH
EXTREME_GEOMETRY_PRESENT_PARENT_CONFLICT
```

## Relationship to EXT-09

EXT-09 stated that the quality of the Extreme itself is secondary.

EXT-10 confirms that same principle for positive and negative examples.

Together:

```text
Extreme quality is downstream of context and zone quality.
```

## Short Formal Statement

A good Extreme is an entry point inside a valid NDS context and potential-rich zone. A deceptive Extreme is a near-node entry that looks precise but lacks valid context, valid zone, or meaningful reward exposure. The Veto Model must therefore learn to veto Extreme geometry when the upstream context and zone do not justify trading it.
