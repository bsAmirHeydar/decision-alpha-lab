# EXT-12 — Normalized Interpretation

## Core Claim

Extreme is not classical support and resistance.

The difference is not simply that both may appear near a price level.

Extreme belongs to NDS because it is defined through:

```text
cycle view
node logic
near-death of cycle
anchor-node invalidation
fractal and scenario context
```

Classical support/resistance is an external ontology and must not enter NDS as a native concept.

## Difference 1 — Cycle View

Classical support/resistance usually treats price levels as areas where price may react.

Extreme treats the level as part of a cycle.

The key NDS question is not:

```text
is this support or resistance?
```

The key NDS question is:

```text
where is the cycle?
where did the cycle start?
where is the cycle close to death?
which node defines that death boundary?
```

So Extreme is tied to the life/death logic of a cycle, not to a generic level-reaction concept.

## Difference 2 — Node View

Extreme is built around NDS node logic.

The node is not merely a support/resistance line.

It is a structural anchor generated by NDS node rules.

For Extreme, the anchor node defines:

```text
near-death zone
entry neighborhood
stop location
structural invalidation
cycle-death boundary
```

This is different from classical support/resistance, where the line often acts as a broad reaction area without NDS-defined cycle death.

## Difference 3 — Near-Death Logic

EXT-01 defined Extreme as a near-death zone around an untouched node.

EXT-06 defined that if price penetrates beyond the cycle-origin node by even one point, the node validity ends.

This gives Extreme a crisp structural boundary:

```text
near death = tradable Extreme area
penetration beyond node = cycle death / invalidation
```

Classical support/resistance does not have this same NDS-native near-death rule.

## Difference 4 — Stop Behind Node

Extreme has NDS-native stop geometry.

The stop goes behind the node because the node is the structural invalidation boundary.

This differs from arbitrary support/resistance stop placement.

In Extreme:

```text
entry = near node death area
stop = behind node
invalidation = node penetrated
reward = opened by reaction from near-death
```

The stop is not just placed beyond a line.

It is placed beyond the structural death boundary of the cycle.

## Difference 5 — Multi-Scenario and Fractal Context

Extreme is not used as a standalone price-level signal.

It is used after the system has established:

```text
context
scenario
zone / region
direction or optionality
parent/current/child relationship
```

This separates Extreme from classical level trading.

A support/resistance trader may say:

```text
price is at resistance, sell
```

NDS should say:

```text
the NDS context and zone justify looking for a local limit reversal entry around this anchor node
```

## Difference 6 — Ontology Boundary

Support/resistance should not enter the system as a native term.

If someone observes something that looks like support/resistance, it must be translated into NDS language.

Allowed translation target:

```text
node
cycle-origin node
anchor node
near-death zone
scenario region
destination
invalidation
```

Forbidden native explanation:

```text
classical support held
resistance rejected price
price bounced from support
```

Those are external ontology phrases.

## AI Relevance

AI must not learn Extreme as generic support/resistance.

AI must learn it as an NDS object:

```text
anchor_node_id
node_level
cycle_origin_node
near_death_zone
entry_direction_relation_to_current_move
stop_behind_node
node_penetration_invalidation
context_valid

```

If the AI starts using support/resistance logic, this is ontology contamination.

## Short Formal Statement

Extreme is separated from classical support/resistance by NDS cycle view and node logic. It is not a generic reaction level; it is a near-death entry zone around an NDS anchor node, used only inside valid context and zone, with stop behind the node and invalidation defined by node penetration.
