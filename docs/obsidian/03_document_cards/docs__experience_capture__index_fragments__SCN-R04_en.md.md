## خلاصه

Path: Summary: A scenario in NDS is created because a set of structural constraints has been respected. Its update, repricing, ranking, veto, or death should be determined by how much of those constraints remain untouched and how its relative weight changes compared with new scenarios or previously existing scenarios that have updated. A scenario can lose rank without dying. Repricing happens when the core constraint identity remains valid but the tradeable expression changes. Death happens when the core constraints that created the scenario are destroyed. Veto means the scenario still exists structurally but is not worth trading. Main derived architecture requirements:
