# Purpose

Adds a new execution policy without creating a new pipeline.

# Responsibilities

A policy receives event, immutable context, and declared parameters; returns a candidate or explicit ineligibility.

# Fast-path constraints

- All authoritative inputs must be available at the declared decision time.
- Work must be bounded by the compiled plan.
- Runtime failures must map to explicit abstention or rejection reason codes.
- No module may silently change strategy canon, model schema, thresholds, or capital limits.

# Forbidden coupling and failure modes

Calling models, allocating volume, reading future bars, or silently changing stop logic by regime.

# Required tests

Directional geometry, price translation, tick normalization, boundary, and identity tests.

# Operational completion criteria

1. The module has a versioned contract and owner.
2. Inputs, outputs, timestamps, units, and missing behavior are explicit.
3. Deterministic replay is possible from stored artifacts.
4. Performance is benchmarked under the intended mode.
5. Failure behavior is fail-closed when the module is authoritative.
6. Migration and rollback are documented.
