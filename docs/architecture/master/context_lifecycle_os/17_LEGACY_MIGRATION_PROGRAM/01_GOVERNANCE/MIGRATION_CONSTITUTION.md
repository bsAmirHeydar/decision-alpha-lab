# Migration Constitution

## Constitutional rules

1. Preserve meaning before improving architecture.
2. Separate observed behavior from intended doctrine.
3. Use stable canonical identities independent of file names.
4. Keep known-time and closed-bar semantics explicit.
5. Treat no-trade, abstention, invalidation and missing data as first-class outputs.
6. Never merge by visual similarity, naming similarity or copied comments.
7. Never let visualization or execution recalculate domain truth.
8. Never remove evidence required to explain past behavior.
9. Every transition is reversible until controlled deletion.
10. Every destructive action requires independent review and a deletion ledger.

## Enforcement

The machine registry, migration packet schemas, phase gates and review checklists implement these rules. A phase may fail closed but may not weaken the constitution to pass.
