# ACL-02 — Context Doctrine Specification

## Purpose

Context Doctrine Specification is a governed part of the Context Standard and Intake boundary. It converts authored Context knowledge into closed, inspectable, versioned and reviewable artifacts without granting compiler, research, runtime, order or capital authority.

## Owned responsibilities

- Enforce exact Context identity, ownership, version and security classification.
- Preserve known-time semantics and explicit UNKNOWN behavior.
- Emit deterministic findings with reason codes and remediation.
- Preserve ACL-00 authority and ACL-01 artifact/lineage identities.
- Record machine-readable evidence and a generated Obsidian projection.

## Inputs

- Exact Context package artifact and content digest.
- Registered schema, policy and plugin versions.
- Subject-bound `ACL02_EVALUATE_CONTEXT` authority permit.
- Authored doctrine, contracts, examples and amendment policy.

## Outputs

- Closed-schema validation and readiness artifacts.
- Missingness, ambiguity, causal-clock, security and semantic findings.
- Maximum lifecycle state `SEMANTICALLY_VALIDATED` after external approval.
- Explicit handoff requirements for [[ACL_03_CONTEXT_COMPILER_AND_ONBOARDING]].

## Invariants

1. Unknown fields and unknown authority fail closed.
2. Vague human language never becomes implicit executable behavior.
3. Event time, known time and decision time remain distinct.
4. Generated projections are not edited by hand.
5. Context semantics never contain order submission or capital activation authority.
6. A passing intake is not evidence of alpha, generalization or profitability.

## Security boundary

This component accepts only declared files inside the Context root, rejects path traversal, enforces minimum classification and mandatory controls, records no inline secret, and exposes no network or broker capability.

## Evolution

Additive questions, linters and projections enter through registered plugins and conformance tests. Breaking semantics require a major Context version, semantic diff, migration, impact analysis and rollback.

## Verification

The reference suite covers schema closure, missing requirements, vague language, clock mutation, owner separation, security underclassification, forged permits, fixture coverage, deterministic projection and clean-checkout delivery.

## Claim ceiling

`SEMANTIC_INTAKE_REFERENCE_ONLY`. This phase cannot claim statistical value, overfit resistance, live parity, production security or capital authorization.
