# Purpose

Force every discovery program to state a causal-economic hypothesis before searching models.

## Capability tier

**Core Production**

## System design

### Mechanism claim

Why the context should alter future path, fill, survival, or treatment utility.

### Observable implications

Expected signatures in MFE, MAE, timing, fill, path smoothness, or tail behavior.

### Boundary conditions

Regimes, markets, sessions, liquidity states, and lifecycle windows where the hypothesis should or should not hold.

### Refutation plan

Nulls, placebos, ablations, shifts, and prospective evidence that could disprove the claim.

## Input contracts

- `ContextDoctrine`
- `ResearchQuestion`
- `MechanismPrior`

## Output contracts

- `HypothesisManifest`
- `NullProgram`
- `RefutationDossier`

## Measurement framework

- Pre-registration completeness.
- Consistency of predicted and observed signatures.
- Refutation survival.

## Adversarial questions

- Is the hypothesis post-hoc storytelling?
- Does it make risky, testable predictions?
- Can it distinguish mechanism from correlation?

## Mandatory controls

1. Exact upstream hashes and data roles are recorded.
2. Candidate and failure ledgers are complete.
3. Costs, capacity, missingness, censoring, and support are explicit.
4. Validation uses chronological, cluster-aware, purged folds.
5. Advanced outputs cannot bypass manual policy, hard risk, portfolio, or UCEE promotion.
6. Any runtime handoff requires deterministic export, parity, latency, fallback, and revocation evidence.

## Acceptance boundary

Passing research metrics is necessary but never sufficient. The component remains non-authoritative until its evidence is admitted through UCEE I12, compiled by I14, challenged prospectively under I15, bounded by I17, and qualified under I18.
