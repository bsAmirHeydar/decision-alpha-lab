# Purpose

Create a defense-in-depth system against temporal leakage, dependence inflation, search overfitting, researcher degrees of freedom, and economic simulation bias.

## Capability tier

**Core Production**

## System design

### Data defenses

Known-time lineage, role firewall, cluster splits, purge, embargo, and locked final test.

### Search defenses

Predeclared spaces, complete trial ledger, nested selection, complexity budget, and multiplicity correction.

### Statistical defenses

Cluster bootstrap, PBO/CSCV, deflated performance, Reality Check/SPA, and sensitivity analysis.

### Economic defenses

Executable costs, capacity, path ambiguity, delay, broker, and fill stress.

### Governance defenses

Exposure ledger, independent adversary, committee review, prospective paper, and signed promotion.

## Input contracts

- `ExperimentFamily`
- `DataRoleMap`
- `TrialLedger`

## Output contracts

- `AntiOverfitDossier`
- `ChallengeResults`
- `PromotionRecommendation`

## Measurement framework

- Leakage incidents.
- Effective trials.
- Selection-adjusted performance.
- Stress survival.
- Prospective delta.

## Adversarial questions

- Can any single defense fail silently?
- Are multiple related experiments excluded from multiplicity?
- Is economic realism added only after selection?

## Mandatory controls

1. Exact upstream hashes and data roles are recorded.
2. Candidate and failure ledgers are complete.
3. Costs, capacity, missingness, censoring, and support are explicit.
4. Validation uses chronological, cluster-aware, purged folds.
5. Advanced outputs cannot bypass manual policy, hard risk, portfolio, or UCEE promotion.
6. Any runtime handoff requires deterministic export, parity, latency, fallback, and revocation evidence.

## Acceptance boundary

Passing research metrics is necessary but never sufficient. The component remains non-authoritative until its evidence is admitted through UCEE I12, compiled by I14, challenged prospectively under I15, bounded by I17, and qualified under I18.
