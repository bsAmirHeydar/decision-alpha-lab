# Late-Fusion Baseline

## Purpose

A simple uniform mean baseline remains available, immutable, and first in the fallback ladder. This note is normative for the deterministic synthetic-reference implementation and must be interpreted together with the machine-readable contracts, frozen upstream evidence, test suite, claim ledger, and authority boundary.

## Engineering specification

V4-15 consumes the exact frozen V4-14 foundation-feature handoff and the immutable V4-04 domain-view package heritage. Every domain view and foundation feature remains separately identifiable by source hash, source plane, known time, quality, age, availability, and support state. The implementation aligns all admissible inputs to a fixed sixteen-dimensional envelope, never treats numeric zero as evidence of presence, and never permits list order to replace semantic identity.

The baseline is a deterministic late-fusion mean. Challengers implement quality-gated, masked cross-attention-shaped, evidential product-of-experts, and disagreement-aware mixture behavior. These are bounded local reference algorithms, not claims of trained production models. Missing required or critical views abstain; corrupt views quarantine; a missing foundation plane routes foundation-dependent challengers to the baseline. Gate concentration is monitored for view collapse, disagreement inflates uncertainty, and attribution remains diagnostic rather than causal.

## Invariants and failure semantics

1. Unknown fields, hash mismatches, dimension changes, future-known inputs, mutable upstream references, or authority escalation fail closed.
2. All 1,024 domain-view subsets and all 64 foundation-view subsets have explicit bounded directives.
3. Required domain views cannot be silently imputed, and critical-view absence cannot be bypassed by foundation features.
4. No output may predict outcomes, rank or select treatments, allocate risk, activate runtime generations, access live credentials, or place orders.
5. Synthetic reference ranking is architecture evidence only and cannot satisfy UCEE promotion, prospective, runtime-parity, or production gates.

## Evidence and review

Evidence includes exact schemas and examples, deterministic Python source, golden aligned envelopes, explicit masks, support audits, exhaustive subset matrices, structured dropout, fusion outputs, disagreement and collapse diagnostics, ablation, permutation, future-suffix and corruption tests, compute/exposure accounting, immutable checkpoints, replay and integrity receipts, detailed Obsidian notes, static MQL5 mirrors, file inventory, manifest, and SHA-256 ledger. Reviewers must verify that claims remain no stronger than this evidence class.
