# Purpose

Describe each validated edge as a reusable, machine-readable economic and operational phenotype.

## Capability tier

**Core Production**

## System design

### Semantic genes

Context family, setup archetype, market, horizon, direction, trigger, and lifecycle.

### Economic genes

Payoff shape, cost sensitivity, fill profile, turnover, capacity, and tail behavior.

### Dependence genes

Symbol, currency, session, anatomy, regime, shared-event, and empirical correlation.

### Operational genes

Latency, data views, runtime tier, broker constraints, monitoring assumptions, and decay signals.

## Input contracts

- `PromotionDossier`
- `AttributionReport`
- `RuntimeTelemetry`

## Output contracts

- `EdgeGenome`
- `TransferPrior`
- `PortfolioProfile`

## Measurement framework

- Genome completeness.
- Cross-context transfer value.
- Portfolio diversification contribution.

## Adversarial questions

- Is a genome inferred from too little evidence?
- Are hidden shared drivers omitted?
- Does transfer create leakage or false priors?

## Mandatory controls

1. Exact upstream hashes and data roles are recorded.
2. Candidate and failure ledgers are complete.
3. Costs, capacity, missingness, censoring, and support are explicit.
4. Validation uses chronological, cluster-aware, purged folds.
5. Advanced outputs cannot bypass manual policy, hard risk, portfolio, or UCEE promotion.
6. Any runtime handoff requires deterministic export, parity, latency, fallback, and revocation evidence.

## Acceptance boundary

Passing research metrics is necessary but never sufficient. The component remains non-authoritative until its evidence is admitted through UCEE I12, compiled by I14, challenged prospectively under I15, bounded by I17, and qualified under I18.
