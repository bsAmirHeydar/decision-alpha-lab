# Purpose

Test whether the selected winner exceeds a universe of alternatives and plausible no-edge constructions.

## Capability tier

**Core Production**

## System design

### Reality Check / SPA

Bootstrap performance differences across the registered candidate universe.

### Matched nulls

Preserve timing, context frequency, costs, holding time, and cluster structure while breaking the hypothesized edge.

### Placebos

Shift timestamps, shuffle direction within blocks, randomize treatment labels, inject noise features, and use pseudo-contexts.

### Interpretation

Null rejection supports evidence but does not establish causal mechanism or production readiness.

## Input contracts

- `CandidateReturns`
- `DependencyBlocks`
- `NullDefinitions`

## Output contracts

- `RealityCheckReport`
- `SPAReport`
- `PlaceboReport`

## Measurement framework

- Null rejection rate.
- Winner margin.
- Bootstrap stability.
- Placebo false-positive rate.

## Adversarial questions

- Is the null too easy?
- Does bootstrap preserve dependence?
- Were nulls chosen after observing the winner?

## Mandatory controls

1. Exact upstream hashes and data roles are recorded.
2. Candidate and failure ledgers are complete.
3. Costs, capacity, missingness, censoring, and support are explicit.
4. Validation uses chronological, cluster-aware, purged folds.
5. Advanced outputs cannot bypass manual policy, hard risk, portfolio, or UCEE promotion.
6. Any runtime handoff requires deterministic export, parity, latency, fallback, and revocation evidence.

## Acceptance boundary

Passing research metrics is necessary but never sufficient. The component remains non-authoritative until its evidence is admitted through UCEE I12, compiled by I14, challenged prospectively under I15, bounded by I17, and qualified under I18.
