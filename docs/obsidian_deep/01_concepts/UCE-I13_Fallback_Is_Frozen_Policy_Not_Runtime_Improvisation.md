# Fallback Is Frozen Policy, Not Runtime Improvisation

## Claim

Each invalid path maps to manual-only, abstain, or reject before runtime observations.

## Formal rule

The rule is represented by a closed contract, canonical identity, executable validator, negative fixture, and retained decision evidence. No consumer may replace the rule with a convenience default.

## Consequence

- Research and runtime must consume the same versioned semantics.
- Failure is visible as reject, abstain, pending approval, or deterministic fallback.
- Behavior-changing fields participate in SHA-256 identity.
- A future observation cannot revise a past decision artifact.
