# Frozen Prospective Paper Plan

## Objective

Freeze runtime generation, time window, minimum decisions, and no-tuning rule.

This chapter is an executable delivery contract. Downstream phases must consume the artifact identities named here and may not reconstruct missing semantics from prose.

## Governing invariants

1. Every behavior-changing field is present in canonical serialization and changes an owning SHA-256 identity.
2. Known-time and causal-cut rules are enforced in executable code; future suffixes cannot rewrite a past occurrence or decision artifact.
3. Fixture evidence may prove contract closure and deterministic orchestration, but it may not be promoted as real-data alpha evidence.
4. Treatment and algorithm universes are frozen before confirmatory outcomes are inspected; mutation creates a new version and a new tournament.
5. Failed, skipped, pruned, rejected, duplicate, stale, and quarantined work remains in the ledger and evidence bundle.
6. Research, tester, paper, and runtime consumers use the same context, treatment, economics, feature, risk, and policy identities.
7. Critical causality, integrity, parity, risk, or prospective-paper failures are non-compensatory vetoes.
8. Generic I15 code and MQL5 mirrors have no broker, network, order, or position authority.

## Contract inputs

- Accepted UCE-I02 context-package identities and exact context observations.
- UCE-I03–I06 treatment, economics, outcome-cube, label, and dataset identities.
- UCE-I07–I11 trainer, algorithm, search, budget, fold, and experiment-ledger identities.
- UCE-I12 signed statistical promotion evidence and blocker status.
- UCE-I13 compiled manual/AI/hybrid policy generation and authority matrix.
- UCE-I14 immutable runtime bundle, parity certificate, activation/rollback identities, and runtime telemetry contract.
- Explicit data inventory classified as fixture, historical real, or prospective paper.

## Processing model

```text
inventory + causal cut
        │
context-package replay and future-perturbation audit
        │
frozen treatment universe + frozen algorithm/task universe
        │
deterministic folds, purge, embargo, budgets, and ledger
        │
reference/infrastructure tournament
        │
confirmatory anti-overfit gate and bounded challengers
        │
frozen prospective paper plan and immutable runtime generation
        │
fill/cost/decision/drift reconciliation
        │
champion, challenge, pending, or legitimate rejection
```

## Required outputs

- Closed JSON artifact with semantic version, stable identity, and explicit source lineage.
- Golden fixture proving acceptance behavior and negative fixture proving refusal behavior.
- Deterministic replay evidence and hash-chained ledger evidence.
- Machine-readable limitations that distinguish infrastructure proof from alpha proof.
- Test, telemetry, operator, rollback, and downstream handoff evidence.

## Failure matrix

| Failure | Detection | Mandatory disposition | Retained evidence |
|---|---|---|---|
| Fixture represented as real data | Inventory mode and source classification | Reject real-data gate | Inventory identity and reason code |
| Outcome/future feature enters context | Feature allow/deny policy and future perturbation | Reject occurrence/package | Feature ID, source, known time |
| Universe changes after outcome inspection | Declared time, outcome cut, hash comparison | New version and new tournament | Old/new universe hashes |
| Fold overlap or leakage | Time-order, purge, embargo validation | Refuse tournament | Fold boundaries and violation |
| Budget-dependent hidden trial | Declared/executed reconciliation | Reject report | Missing trial identity |
| Failed work removed | Ledger and declared universe reconciliation | Reject evidence bundle | Expected/actual ledger entries |
| Paper period tuned or retrained | Frozen plan and generation hashes | Invalidate paper period | Mutation and operator record |
| Missing or mismatched fill/cost | Reconciliation engine | Mismatch or missing status | Expected/observed values |
| Critical gate fails | Champion gate | Reject; no score compensation | Gate vector and reasons |
| Order authority appears in generic layer | Static boundary checks | Block delivery | File and forbidden token |

## Mandatory executable tests

- Repeated canonical inputs produce identical inventory, freeze, trial, report, paper, and decision hashes.
- One behavior-bearing mutation changes its owning hash.
- Future-suffix observations do not change prefix context replay.
- Forbidden future/outcome fields are refused before feature construction.
- Declared trial count equals the full context × treatment × algorithm × fold universe.
- Injected failed trials remain present and counted.
- Reference fixtures end in rejection rather than synthetic promotion.
- A completed untouched prospective report may promote only with all critical gates and a valid promotion bundle.
- Duplicate decisions, missing fills, cost mismatches, touched paper periods, and incomplete windows fail closed.
- Python and MQL5 mirror the same critical gate semantics; static checks do not claim MetaEditor compilation.

## Telemetry and retained evidence

- Inventory, dataset, schema, context, treatment, algorithm, fold, freeze, trial, report, plan, paper, decision, and bundle hashes.
- Declared, executed, succeeded, failed, skipped, pruned, and rejected counts.
- Context known time, maturity, freshness, lifecycle, source IDs, and causal-cut status.
- Expected and observed entry, exit, cost, decision, latency, duplicate, and drift fields.
- Gate vector, reasons, operator actions, limitations, and upstream routing.

## Operator controls

1. Verify inventory mode and source lineage before running any tournament.
2. Sign and freeze context, treatment, algorithm, metrics, gates, folds, budgets, and final-test seal.
3. Run infrastructure pilots without editing generated artifacts manually.
4. Preserve all failures and reconcile the full declared universe.
5. Freeze one prospective paper plan and one immutable I14 generation; tuning and retraining are prohibited.
6. Do not promote from fixtures, incomplete paper periods, mismatches, or critical findings.
7. Route rejection to the owning upstream phase instead of patching around the gate.

## Residual-risk statement

The delivered reference fixtures prove serialization closure, causality controls, deterministic tournament enumeration, ledger retention, prospective-plan immutability, reconciliation behavior, and legitimate rejection. They do not establish market edge, sufficient sample size, broker-fill realism, production key custody, operating-system crash behavior, or a completed real prospective paper period. Those claims require externally supplied real data and observed paper evidence.

## Chapter-specific acceptance

- Any unresolved dependency is represented as pending or rejected, never silently assumed.
- The reference delivery does not assert real-market alpha or a completed prospective paper period.
