# Implementation Roadmap — Setup AI Edge Discovery

## Delivery Principle

Build one golden vertical slice on EXP0017/F2 while centralizing reusable registries and contracts. Do not build a generic UI disconnected from a real Context, and do not create a one-off EXP0017 stack.

## Phases

| Phase | Mission |
|---|---|
| SAED-00 | gap audit, architecture freeze and contract crosswalk |
| SAED-01 | payoff, entry, trigger and objective registries |
| SAED-02 | Setup archetype and compatibility compiler |
| SAED-03 | complete Treatment universe and identity |
| SAED-04 | path-accurate outcome cube and fill models |
| SAED-05 | candidate-level dataset, maturity and folds |
| SAED-06 | manual baselines and descriptive style study |
| SAED-07 | eligibility/fill/outcome trainer tasks |
| SAED-08 | ranking and Treatment-choice tournament |
| SAED-09 | survival, distributional and trail/path pack |
| SAED-10 | regime, novelty and multi-view challengers |
| SAED-11 | experiment DAG, budgets and full ledgers |
| SAED-12 | anti-overfit, nulls, stresses and promotion dossier |
| SAED-13 | manual/AI/hybrid graph and abstention/fallback |
| SAED-14 | immutable runtime handoff and MQL5 parity |
| SAED-15 | frozen prospective paper challenge |
| SAED-16 | onboarding template for all Context families |

## Acceptance of the Program

The architecture succeeds even if all Setup candidates are rejected, provided the rejection is causal, reproducible, economically realistic and preserved in Failure Memory.
