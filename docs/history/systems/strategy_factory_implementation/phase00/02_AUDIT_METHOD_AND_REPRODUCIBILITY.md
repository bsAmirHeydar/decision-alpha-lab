# Audit Method and Reproducibility

## Design principle

The audit must be runnable from a clean checkout without relying on the researcher's memory. A human narrative is useful, but the phase gate depends on machine-readable evidence generated by code.

## Auditor architecture

```text
Repository root
├── File scanner
├── Contract extractor
├── Module classifier
├── Duplicate capability detector
├── Execution authority scanner
├── Test baseline collector
├── Risk builder
└── Artifact writer
```

The implementation lives under:

```text
lab/11_strategy_factory/phase00_current_state_audit/
```

The auditor is deliberately standard-library-first. Its repository scan does not require pandas, MetaTrader5, or a live terminal.

## File inventory

For every non-Git file, the scanner records:

- relative path;
- extension;
- byte size;
- line count where text-readable;
- SHA-256;
- binary/text status;
- empty status;
- category.

The SHA-256 allows duplicate or replayed files to be identified without trusting names. Sorted traversal makes the output stable across runs on the same checkout.

## Contract discovery

Python files are parsed with the abstract syntax tree. The auditor records:

- top-level classes;
- public methods;
- top-level public functions;
- imports;
- source path.

This is not the final contract system. It is a map of **implicit contracts that already exist** and therefore must be considered during Phase 01.

## Execution-authority scan

The scanner looks for executable occurrences of:

- `OrderSend(`
- `OrderCheck(`
- `CTrade`
- `mt5.order_send(`
- `mt5.order_check(`
- likely broker `buy`, `sell`, or order-submission methods

Comment-only lines are ignored. Every executable occurrence is reported with path, line number, token, severity, and snippet.

A zero-result scan does not prove that capital is universally safe. It proves that the audited snapshot contains no identified call site matching the configured authority patterns. The scan must be rerun after every execution-related change.

## Test baseline

The auditor runs:

```text
python -m compileall -q lab
python -m pytest -q
```

It stores return codes and bounded output. A failing old test baseline does not block the inventory if the failure is fully identified and assigned to a later phase, but it is never hidden.

## Determinism

The following outputs should be deterministic for a fixed repository checkout and tool version:

- repository inventory ordering;
- SHA-256 values;
- module classification;
- contract map;
- duplicate matrix;
- authority findings;
- risk IDs and ownership.

Run timestamps and environment-specific test output are observational metadata and are not part of semantic equivalence.

## Failure behavior

The auditor fails closed when:

- the supplied root lacks `lab` or `docs`;
- configuration cannot be interpreted;
- required output paths cannot be written;
- an unsupported schema major is supplied.

The authority scan does not silently discard decoding problems; it reads source with replacement and still reports matching executable text.

## Reproduction command

```powershell
python .\lab\11_strategy_factory\phase00_current_state_audit\run_audit.py `
  --repo-root . `
  --output .\lab\11_strategy_factory\phase00_current_state_audit\artifacts
```

## Verification command

```powershell
pytest -q .\lab\11_strategy_factory\phase00_current_state_audit\tests
```

Expected Phase 00 result:

```text
13 passed
```
