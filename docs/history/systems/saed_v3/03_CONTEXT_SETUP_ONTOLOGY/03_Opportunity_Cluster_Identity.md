# Purpose

Represent every context occurrence and all sibling treatments as one dependent opportunity cluster.

## Capability tier

**Core Production**

## System design

### Cluster key

Deterministic identity from context occurrence, known time, market, and source lineage.

### Sibling set

All compiler-approved treatments, including skip and non-fill outcomes.

### Split discipline

The whole cluster belongs to exactly one chronological fold and data role.

### Portfolio link

Multiple contexts generated by the same market event may also carry a higher-order shared-event cluster.

## Input contracts

- `ContextOccurrence`
- `TreatmentUniverseManifest`

## Output contracts

- `OpportunityCluster`
- `SharedEventCluster`
- `FoldAssignment`

## Measurement framework

- No sibling leakage across folds.
- Effective independent opportunity count.
- Shared-event concentration.

## Adversarial questions

- Are candidate rows incorrectly treated as independent?
- Can a discarded treatment disappear from the trial universe?
- Are overlapping contexts double-counted?

## Mandatory controls

1. Exact upstream hashes and data roles are recorded.
2. Candidate and failure ledgers are complete.
3. Costs, capacity, missingness, censoring, and support are explicit.
4. Validation uses chronological, cluster-aware, purged folds.
5. Advanced outputs cannot bypass manual policy, hard risk, portfolio, or UCEE promotion.
6. Any runtime handoff requires deterministic export, parity, latency, fallback, and revocation evidence.

## Acceptance boundary

Passing research metrics is necessary but never sufficient. The component remains non-authoritative until its evidence is admitted through UCEE I12, compiled by I14, challenged prospectively under I15, bounded by I17, and qualified under I18.
