# Purpose

Turn failed hypotheses, brittle models, invalid data paths, and operational incidents into reusable defenses.

## Capability tier

**Core Production**

## System design

### Failure taxonomy

No edge, leakage, selection, instability, cost, capacity, support, causal, parity, execution, governance, and security.

### Failure signature

Context, conditions, metrics, artifacts, root cause, and diagnostic tests.

### Reuse

New programs automatically search for similar failures and inherit mandatory challenges.

### Retesting

A failed idea can return only with a materially new mechanism, data, or control and a new identity.

## Input contracts

- `RejectedPrograms`
- `Incidents`
- `AdversarialReports`

## Output contracts

- `FailureCards`
- `MandatoryChallengeRules`
- `SimilarityLinks`

## Measurement framework

- Prevented duplicate failures.
- Inherited test coverage.
- Failure recurrence.
- Resolution quality.

## Adversarial questions

- Are failures hidden as abandoned experiments?
- Does a new name bypass prior evidence?
- Are transient infrastructure failures confused with scientific rejection?

## Mandatory controls

1. Exact upstream hashes and data roles are recorded.
2. Candidate and failure ledgers are complete.
3. Costs, capacity, missingness, censoring, and support are explicit.
4. Validation uses chronological, cluster-aware, purged folds.
5. Advanced outputs cannot bypass manual policy, hard risk, portfolio, or UCEE promotion.
6. Any runtime handoff requires deterministic export, parity, latency, fallback, and revocation evidence.

## Acceptance boundary

Passing research metrics is necessary but never sufficient. The component remains non-authoritative until its evidence is admitted through UCEE I12, compiled by I14, challenged prospectively under I15, bounded by I17, and qualified under I18.
