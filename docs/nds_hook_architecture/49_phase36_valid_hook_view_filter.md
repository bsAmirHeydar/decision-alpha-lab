# Phase 36 — Valid Hook View Filter

## Doctrine

The production Hook view must not display every Hook candidate generated by the sequence builder. It must display only Hook structures that are valid under the Alpha Lab Hook doctrine.

A Hook is production-visible in valid-only mode when it belongs to one of these families:

1. **Hook After Opposing F3**
2. **Hook After Hook**

There is one explicit visibility companion rule:

> If a Hook is valid because it is the second Hook after a previous Hook, the first Hook must also be displayed so the Hook-after-Hook relation is visually readable.

The first Hook is not upgraded to a valid independent Hook. It is displayed as the required parent of a valid second Hook.

## Accepted Families

### Hook After Opposing F3

A Hook is valid if an opposing F3 is completed/locked before the Hook starts.

This means the F3 creates a broad reversal environment, and the following Hook provides a more concrete structural risk object.

### Hook After Hook

A Hook is valid if:

```text
previous_hook.resolve_node_id == current_hook.origin_node_id
```

The terminal node of Hook-1 is exactly the origin node of Hook-2.

In this family, the second Hook is the valid Hook. The first Hook is visible only as the chain parent.

## Hidden Structures

In valid-only mode, the renderer must hide:

- standalone Hook candidates
- Hook-like fractal noise
- valid/renderable Hooks that are not in a valid family
- first Hooks that are not followed by a valid second Hook

## Implementation

The renderer now separates two filters:

```text
base draw filter
valid-family filter
```

The valid-family filter chooses the valid Hook objects. Then a companion-expansion step adds the immediate parent Hook of every selected Hook-after-Hook child.

This preserves clean production visibility without losing the structural context of the Hook-after-Hook family.

## Scope

This patch affects Hook Phase 02 rendering and input defaults only. It does not change F logic, Rally logic, Zone logic, trade execution, order sending, broker behavior, or risk sizing.
