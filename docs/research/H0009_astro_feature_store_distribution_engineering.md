# H0009 — Astro Feature Store for Distribution Engineering

## Title

**Astro Distribution Engineering: Candle-Aligned Planetary State as a Causal Feature Layer**

## Thesis

Decision Alpha Lab does not treat astrology as a belief system. It treats planetary state as a high-dimensional time feature layer.

The scientific question is not:

```text
Do planets predict markets?
```

The research question is:

```text
Does the distribution of an execution's outcomes change under specific candle-aligned astronomical states?
```

The project focus is therefore shifted from raw edge hunting to **Distribution Engineering**.

A strategy generates trades.  
The Astro Feature Store attaches a deterministic sky-state vector to each candle.  
The Distribution Miner measures whether specific state buckets reshape outcome distributions, win clustering, sequence lift, and loss hazard.  
Roulette / Jackpot execution is allowed only when the engineered distribution shows conditional sequence behavior.

## Core Design

```text
Python Swiss Ephemeris Builder
→ candle-by-candle astro feature CSV
→ MQL5 Astro Feature Store
→ Execution Adapter
→ Distribution Engineering Miner
→ Cluster Filter / Roulette Gate
```

## Time Contract

All rows are aligned to broker candle open time.

```text
broker_time = UTC + broker_gmt_offset_hours
utc_time    = broker_time - broker_gmt_offset_hours
```

The Python builder receives broker dates and broker GMT offset. It converts each broker candle-open timestamp to UTC before calculating the ephemeris.

The MQL5 runtime then matches:

```text
iTime(symbol, timeframe, 0) == broker_time in CSV
```

This makes Strategy Tester and visual tester deterministic.

## Causality Contract

Every feature row is computed at candle open time. No future market outcome is used. No future astrological state is required for the row itself, except optional applying/separating approximations derived from instantaneous planetary speed, not from future market bars.

## Strongest Practical Engine

The first implementation uses `pyswisseph` / Swiss Ephemeris as the primary offline ephemeris engine.

The MQL5 side does not calculate ephemerides. It loads deterministic feature stores generated by Python. This keeps execution and Strategy Tester stable while allowing Python to produce a complete sky map candle by candle.

### Distribution Key

The Python builder creates a high-level causal `feature_key`, for example:

```text
moon_phase=waxing_gibbous|sun_sign=aries|mars_sign=leo|saturn_retro=0|mars_saturn_asp=trine|mars_saturn_app=1
```

Execution modules can append this key to their own market-regime feature keys before sending outcomes to EXP0012 Distribution Engineering.

## Required Tests

For each execution, measure:

```text
raw win rate
filtered astro win rate
lift vs raw
P(W | previous W, astro bucket)
P(W | previous WW, astro bucket)
P(W | previous WWW, astro bucket)
clusters >= 3
clusters >= 5
clusters >= 7
clusters >= 10
loss hazard after k wins
mean R
profit factor
sample size
out-of-sample stability
```

No astro state is allowed into execution unless it improves distributional clustering out-of-sample.

## Overfit Controls

Astrology produces many possible features. This creates extreme overfit risk.

Therefore, valid filters require:

```text
minimum sample size
walk-forward validation
out-of-sample lift
sequence lift, not only win-rate lift
permutation/random baseline
no manual cherry-picking after seeing outcomes
```

## Summary

H0009 adds a deterministic, candle-aligned sky-state feature layer to Decision Alpha Lab.

It does not claim causality. It tests whether planetary state can be used as a measurable feature family for Distribution Engineering.

The core object is not astrology itself. The core object is the conditional outcome distribution after attaching astronomical state to executions.
