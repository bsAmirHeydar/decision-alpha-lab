# Implementation Program

## 1. Delivery Strategy

Build one complete real vertical slice while centralizing every reusable mechanism encountered. Avoid:

- an abstract platform with no real context;
- separate strategy stacks that repeat infrastructure.

## 2. Phase A — Canonical Contracts

Deliver IDs, lineage, market event, context, treatment, outcome, dataset, trial, evidence, capital and runtime schemas. Prove one synthetic opportunity can travel end to end.

## 3. Phase B — Context Factory

Deliver Market Truth, Context SDK/compiler, lifecycle framework, reusable primitives, scenario/replay harness and one golden context with cross-mode parity.

## 4. Phase C — Setup Factory

Deliver manual policy contract, treatment atoms, compatibility graph, objective profiles, abstention, trainer SDK, baseline ladder and manual/AI policies for the golden context.

## 5. Phase D — Research and Evidence

Deliver experiment compiler, exposure/trial ledger, outcome/economics, dataset/folds, statistics, Monte Carlo, anti-overfit, null generator, evidence states, AI Analyst and Failure Memory.

## 6. Phase E — Capital and Portfolio

Deliver money-management policies, separate capital validation, edge genome, portfolio dependence, allocation, reservation and capacity.

## 7. Phase F — Runtime, Security and Execution

Deliver runtime compiler, fixed fast path, decision envelope, hard risk gate, broker adapters, reconciliation, licensing, telemetry, kill and rollback.

## 8. Phase G — Monitoring and Meta-Learning

Deliver machine-readable assumptions, drift and health, champion/challenger, governed retraining, Research Memory, meta-features and Active Experiment Planner.

## 9. Golden Vertical Slice Definition

The slice is complete only when it covers:

```text
Doctrine
→ Context
→ Human Setup
→ AI Tournament
→ Outcome
→ Protected Evidence
→ Capital
→ Portfolio
→ Runtime
→ Paper/Shadow
→ Monitoring
```

It is considered successful even if every setup is rejected, provided the rejection is trustworthy, reproducible and becomes reusable failure knowledge.

## 10. Development Rhythm

Use alternating cycles:

```text
Expansion cycle
→ build capability and discover domain requirements

Consolidation cycle
→ unify contracts, delete duplication, strengthen tests and automate artifacts
```

This preserves speed without letting architectural entropy erase the compounding effect.
