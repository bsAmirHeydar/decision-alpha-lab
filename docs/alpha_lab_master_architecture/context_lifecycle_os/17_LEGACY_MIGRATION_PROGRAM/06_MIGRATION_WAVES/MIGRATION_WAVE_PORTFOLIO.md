# Migration Wave Portfolio

Wave order is based on dependency and risk, not business importance or age. Every wave begins with a fresh ownership and reachability review.

| Wave | Scope | Entry condition | Exit condition |
|---|---|---|---|
| 00 | protect platform; characterize shared primitives | LCM-06 complete | no kernel contamination; engine candidates ranked |
| 01 | low-risk read-only pilot | one owned simple family | complete packet and parity |
| 02 | M-series and research contexts | harness proven | package boundaries stable |
| 03 | EXP0018 Daye Trader | time/session engines stable | MTF, session and drawing parity |
| 04 | EXP0015/16/17 intermarket | reference and divergence primitives stable | context/setup/treatment split and parity |
| 05 | EXP0019 Faerie Protocol | shared cores and arbitration contracts stable | all owner decisions/open decisions preserved |
| 06 | FlagCounting/NDS/Hook/Zone | execution isolation framework proven | state, file, drawing and order paths separated |
| 07 | E-series, CG/STC and Astro execution | all domain packages canonical | dry request parity and security approval |
| 08 | docs/root/archive cleanup | all active cutovers complete | redirects, quarantine and deletion ledger complete |
