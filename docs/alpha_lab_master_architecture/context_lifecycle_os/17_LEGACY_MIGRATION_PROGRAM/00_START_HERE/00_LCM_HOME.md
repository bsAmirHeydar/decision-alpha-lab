# Legacy Context Migration Program — Home

LCM is the controlled migration program that moves historical Contexts, Setups, Treatments, visualizers, platform adapters and their documentation into ACL-OS without silently changing trading semantics.

## Program outcome

The program ends with one canonical location and identity for every active domain artifact, complete behavioral traceability to its legacy source, explicit ownership, deterministic parity evidence, safe redirects, quarantine records and a controlled deletion ledger.

LCM is not a new alpha-discovery phase and is not permission to rewrite old logic. Its first duty is preservation of meaning. Its second duty is removal of structural disorder. Its third duty is safe connection to the lifecycle OS.

## Phase model

`LCM-00` through `LCM-16` remain the authoritative master phases. `LCM-00` through `LCM-07` are already delivered as bounded reference phases. The heavy implementation phases `LCM-08` through `LCM-16` are now executed through a balanced partition of two or three subphases each. The partition changes delivery granularity, not lifecycle meaning or gate strength.

The next approved implementation unit is [[LCM_10C_DRY_RUN_PARITY_SAFETY_CONTROLS_AND_AUTHORITY_NEGATIVE_CLOSURE|LCM-10C — Dry-Run Parity, Safety Controls and Authority-Negative Closure]].

## Claim ceiling

`LEGACY_MIGRATION_PROGRAM_REFERENCE_ONLY`

The program may create migration evidence, canonical packages, compatibility adapters, parity reports, bounded cutovers, quarantine and approved deletion records. It does not prove alpha, authorize production, create live-order authority or activate capital.
