# Implementation Master Plan

Implementation is divided into sixteen independently testable phases.

## Program sequence

ACL-00 Constitution and authority; ACL-01 repository, identity and locator; ACL-02 Context standard and intake; ACL-03 Context compiler/onboarding; ACL-04 dual Setup factory; ACL-05 immutable Batch/store; ACL-06 research DAG; ACL-07 unified validation; ACL-08 reporting/experience; ACL-09 memory/planner; ACL-10 promotion; ACL-11 runtime parity/handoff; ACL-12 security hardening; ACL-13 one-hour product; ACL-14 first real Context pilot; ACL-15 fleet operations and closure.

## Phase delivery contract

Every phase must deliver closed schemas, reference code, unit/property/mutation/integration tests, a threat-model delta, migrations and rollback, English Obsidian documentation, inventory and hashes, a clean-checkout validator, external-gate declarations and a precise handoff.

## Why this order

Authority and identity precede automation. Context and Setup contracts precede experiments. Immutable evidence precedes statistics. Promotion and runtime follow evidence integrity. Security begins in ACL-00 and receives dedicated hardening before any real pilot.

## Program closure

The program closes only when a new Context needs no kernel edit, the one-hour product is reproducible, a full Batch produces complete evidence and reports, runtime parity is proven, security drills pass and every decision traces back to doctrine and immutable evidence.
