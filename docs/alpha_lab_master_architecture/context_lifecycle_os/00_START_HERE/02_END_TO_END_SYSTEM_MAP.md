# End-to-End System Map

The standard flow is contract-driven and fail-closed.

## Lifecycle flow

1. Intake expert doctrine and examples.
2. Validate semantic, temporal, data and security completeness.
3. Compile Context detector IR, occurrence identity and fixtures.
4. Build a known-time-safe occurrence ledger and feature views.
5. Compile human Setup DSL and generate bounded AI candidates into one Setup IR.
6. Freeze data, candidates, models, splits, costs, budgets, seeds, code and environment into an immutable Batch.
7. Run baselines, training, stress, overfit and generalization through a resumable DAG.
8. Generate structured reports and durable experience automatically.
9. Decide promotion using hard guardrails and objective ranking.
10. Compile, sign and parity-test a runtime generation.
11. Progress through paper, shadow and micro-live.
12. Surveil, restrict, quarantine, retire and convert observations into new governed research.

## Cross-cutting rails

Global identity and lineage, policy, security, observability, artifact storage, schema evolution, migration and audit apply to every step. A component cannot privately replace those rails.

## Feedback law

Production observations do not directly change an active model or doctrine. They become experience, then a proposal, a new Batch, new evidence, a new promotion decision and a new runtime generation.
