# Document Succession, Redirect, Deletion and Archive

## Succession record

When a note is replaced, the record identifies old ID and path, successor ID and path, semantic relationship, preserved history and consumer updates.

## Redirect policy

Redirects are temporary compatibility tools, observable where possible and assigned an expiry. Permanent forests of redirect notes are prohibited.

## Deletion

A superseded note is removed from the active branch after references are rewritten, historical recovery is proven and no consumer requires the old path.

## Archive

Historical delivery material belongs in immutable Git history, release bundles or an indexed archive—not mixed with current architecture navigation.
