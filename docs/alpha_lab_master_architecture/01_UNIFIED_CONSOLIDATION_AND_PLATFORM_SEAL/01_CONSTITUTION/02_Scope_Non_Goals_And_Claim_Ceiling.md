# Scope, Non-Goals and Claim Ceiling

## In scope

- all repository files, Git LFS objects and generated artifacts currently treated as project assets;
- Python, MQL5, PowerShell, configuration, schemas, registries and documentation;
- internal and external consumers, terminal profiles, CI jobs and automation;
- package ownership, naming, dependency direction and storage boundaries;
- universal Context lifecycle and operator experience;
- actual cutover and deletion of obsolete duplicates.

## Non-goals

- inventing new trading alpha during consolidation;
- optimizing strategy performance merely to make parity pass;
- granting live-order or capital authority;
- preserving every obsolete file in the active branch;
- rewriting semantics when a move-only change is sufficient;
- replacing evidence with AI confidence.

## Claim ceiling

`PLATFORM_CONSOLIDATION_AND_MECHANIZATION_ONLY`

A successful program proves structural coherence, preserved semantics, deterministic workflows and operational readiness. It does not prove that a Context is profitable or fit for capital.

## Change freeze

New Context families, model families or execution features are frozen unless they are necessary to prove the universal platform. Safety, defect repair and consolidation-enabling changes remain allowed.
