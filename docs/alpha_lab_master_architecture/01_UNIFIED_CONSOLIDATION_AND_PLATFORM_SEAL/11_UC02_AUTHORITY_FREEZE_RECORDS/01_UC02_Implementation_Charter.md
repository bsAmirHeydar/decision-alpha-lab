# UC-02 Implementation Charter

## Mission

UC-02 converts the preserved UC-01 repository state into an explicit, machine-enforced authority model. It assigns every artifact and discovered code symbol to one canonical owner, one target boundary, one planning disposition and one migration wave. It does not move, merge or delete production assets.

## Inputs

- the accepted UC-01 immutable baseline and handoff;
- the current repository tree after the bounded UC-01 syntax stabilization;
- the approved canonical target state;
- all existing architecture contracts, registries and behavior evidence.

## Outputs

- an approved architecture constitution;
- naming, identity, version and path standards;
- a repository-wide artifact authority ledger;
- Python and MQL5 capability ownership ledgers;
- package and system disposition ledgers;
- documentation authority and succession rules;
- differential root and parallel-engine guards;
- a hash-bound UC-03 handoff.

## Claim ceiling

UC-02 may classify and freeze authority. It may not relocate source, rewrite imports, merge behavior, retire a consumer, delete a file, activate runtime, authorize orders or allocate capital.

## Exit rule

The stage is accepted only when all artifacts have a non-unknown disposition, every production capability has exactly one owner, every legacy system has a destination, the guards reject hostile additions, outputs rebuild deterministically and UC-01 remains accepted.
