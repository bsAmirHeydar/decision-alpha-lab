# EXP0017 Phase 01 — Time Anatomy Specification

## 1. هدف فاز

فاز ۱، ستون زمانی کل پروژه است. ربات هنوز قرار نیست معامله‌گر باشد؛ قرار است **زمان‌شناس استراتژی** باشد.

در این فاز ربات فقط باید بداند:

1. روز معاملاتی از کجا شروع می‌شود.
2. روز معاملاتی کجا تمام می‌شود.
3. هر سایکل‌گروپ چگونه روز را تکه‌تکه می‌کند.
4. سایکل جاری هر CG چیست.
5. سایکل‌های قبلی همان روز برای هر CG کدام‌اند.
6. کدام CG در آخر روز سایکل ناقص دارد.

## 2. مرز روز معاملاتی

روز معاملاتی EXP0017 به‌صورت نیویورک تعریف می‌شود:

```text
Start: 18:00 New York
End:   17:00 New York next day
Length: 23 hours = 1380 minutes
```

این یعنی ساعت 17:00 تا 17:59 نیویورک داخل میدان فعال استراتژی نیست. در این بازه ربات باید بگوید بیرون از میدان روز معاملاتی هستیم.

## 3. منطق تبدیل زمان

اکسپرت با زمان بروکر کار می‌کند، اما استراتژی با زمان نیویورک تعریف شده است.

ورودی‌ها:

```text
Broker UTC Offset: default +3
New York DST Auto: default true
Manual New York UTC Offset: default -5
```

اگر Auto DST روشن باشد، offset نیویورک به‌صورت تقریبی بر اساس قانون DST آمریکا محاسبه می‌شود:

- از دومین یکشنبه مارس: UTC-4
- از اولین یکشنبه نوامبر: UTC-5

اگر Auto DST خاموش باشد، مقدار دستی استفاده می‌شود.

## 4. سایکل‌گروپ‌ها

تمام CGهای زیر در رجیستری فاز ۱ تعریف شده‌اند:

```text
cg_3m, cg_5m, cg_9m, cg_10m, cg_15m, cg_18m, cg_20m, cg_24m,
cg_30m, cg_40m, cg_45m, cg_60m, cg_72m, cg_90m, cg_120m,
cg_150m, cg_180m, cg_240m, cg_300m, cg_360m, cg_720m
```

هر CG یک خانواده مستقل زمانی است. هیچ CG در فاز ۱ نسبت به CG دیگر اولویت ندارد.

## 5. سایکل جاری

برای هر CG:

```text
cycle_index = elapsed_minutes_from_18NY / cg_minutes
cycle_start = trading_day_start + cycle_index * cg_minutes
cycle_end = min(cycle_start + cg_minutes, trading_day_end)
```

برای نمایش انسانی، انتهای سایکل به‌صورت دقیقه آخر نمایش داده می‌شود. مثال `cg_30m`:

```text
18:00-18:29
18:30-18:59
19:00-19:29
...
```

اما در منطق داخلی، انتهای سایکل **exclusive** است. یعنی سایکل اول `18:00 <= time < 18:30` است.

## 6. سایکل‌های قبلی همان روز

طبق داکترین فصل ۴، همه سایکل‌های پیشین همان روز می‌توانند در فازهای بعدی مرجع باشند. فاز ۱ هنوز reference high/low نمی‌سازد، اما باید تعداد و مرزهای زمانی آن‌ها را آماده کند.

برای سایکل شماره N:

```text
previous_cycle_count = N - 1
```

## 7. سایکل ناقص آخر روز

چون روز معاملاتی ۱۳۸۰ دقیقه است، بعضی CGها آخر روز سایکل ناقص دارند. مثال:

- `cg_180m`: ۱۳۸۰ بر ۱۸۰ بخش‌پذیر نیست؛ آخرین سایکل ناقص است.
- `cg_720m`: دو سایکل دارد؛ سایکل دوم از نظر طول نسبت به 720 دقیقه ناقص است.

فاز ۱ این وضعیت را با فیلد `partial-last` نمایش می‌دهد.

## 8. خروجی چارت

اکسپرت روی چارت یک پنل متنی می‌سازد که نشان می‌دهد:

- زمان بروکر
- زمان UTC
- زمان نیویورک
- شروع/پایان روز معاملاتی نیویورک
- وضعیت داخل/خارج روز معاملاتی
- برای هر CG فعال: سایکل جاری، تعداد کل سایکل‌ها، بازه سایکل، تعداد سایکل‌های قبلی، زمان باقی‌مانده

## 9. چیزهایی که در فاز ۱ عمداً وجود ندارند

- هانت
- واگرایی
- تأیید با کلوز کندل
- نماد hunter / clean
- مرجع high/low
- استاپ

- معامله
- آمار outcome
- مدل رتبه‌دهنده

## 10. معیار موفقیت فاز

فاز ۱ زمانی موفق است که بتوانیم اکسپرت را روی چارت بیندازیم و ببینیم زمان‌ها، CGها و سایکل‌های جاری دقیقاً مطابق منطق 18:00 تا 17:00 نیویورک ساخته می‌شوند.
