# Phase 14 — One-Shot Divergence Signal Execution Contract

## Status

This document defines a hard execution invariant for EXP0017. It is not an optional filter and it is not a tunable strategy parameter.

```text
One divergence anatomy = one execution entitlement = at most one entry opportunity.
```

A divergence may remain visible and may be rediscovered on many lower-timeframe closed candles. Those repeated observations do not create new trade permissions.

## 1. Why this contract exists

The confirmation engine evaluates the market at every newly closed candle of the configured confirmation timeframe. A valid CG divergence can remain valid across multiple such candles. Without an anatomy-scoped gate, the executor could create one order per lower-timeframe candle for the same underlying divergence.

That behavior would incorrectly transform persistence of one signal into multiple independent signals. It would also distort backtest trade count, risk exposure, drawdown, CG statistics, and all later AI training data.

## 2. Signal observation versus trade entitlement

These concepts are separate:

- **Signal observation:** the confirmation engine reports that a divergence is valid at a particular closed-candle boundary.
- **Trade entitlement:** the executor is permitted to act on the underlying divergence anatomy once.

A signal can have many observations but only one entitlement.

```text
Observation at lower candle T1 ┐
Observation at lower candle T2 ├─ same divergence entitlement
Observation at lower candle T3 ┘

Only T1 may consume the entitlement.
T2 and T3 are suppressed.
```

## 3. Canonical entitlement identity

The entitlement key is generated by `CGX_BuildTradeEntitlementKey()` and versioned as `CGX_ONCE_V1`.

It contains:

- canonical, order-independent symbol pair;
- CG name;
- New York trading-day start;
- current-cycle start;
- reference-cycle start;
- divergence side: HIGH or LOW.

It deliberately excludes:

- confirmation candle time;
- confirmation timeframe;
- lower-timeframe bar index;
- entry model;
- stop model;
- target model;
- volume model;
- selected trade leg;
- order ticket;
- position state.

Conceptually:

```text
entitlement_key =
  version
  + canonical_symbol_pair
  + cycle_group
  + trading_day
  + current_cycle
  + reference_cycle
  + divergence_side
```

This makes the key stable while the same divergence is repeatedly detected on later lower-timeframe candles.

## 4. Symbol-order invariance

The pair is canonicalized before key construction.

```text
SPXUSD / NDXUSD == NDXUSD / SPXUSD
```

Reversing `Symbol A` and `Symbol B` cannot generate a second entitlement for the same market anatomy.

## 5. Consumption point

The entitlement is consumed at the first eligible closed-candle observation, before:

1. trade planning;
2. quote validation;
3. stop and target construction;
4. volume calculation;
5. position-policy checks;
6. broker routing.

```text
confirmed signal
→ build entitlement key
→ consume one-shot entitlement
→ build trade plan
→ route order
```

This ordering is mandatory.

## 6. No retry semantics

Consumption means the signal has used its single right to enter. The entitlement remains consumed even when:

- spread is too high;
- quote is stale;
- stop geometry is invalid;
- volume cannot satisfy the fixed-risk ceiling;
- hedge or position policy blocks the order;
- broker transport fails;
- the order is rejected;
- the runtime is paper-only.

The executor does not wait for a later candle to obtain a more favorable entry from the same divergence. A later retry would be a second entry opportunity and would violate this contract.

If retry behavior is ever researched, it must be implemented as a separate, explicitly versioned execution policy and must not weaken `CGX_ONCE_V1` silently.

## 7. Multiple positions and hedging

One-shot identity is independent of position policy.

- Hedging ON does not allow the same divergence to enter twice.
- `CGX_POSITION_EVERY_SIGNAL` means every distinct divergence signal may trade; it does not mean every repeated observation may trade.
- Different CGs may each create distinct entitlements.
- Different reference cycles create distinct entitlements.
- Different current cycles create distinct entitlements.
- HIGH-side and LOW-side divergence are distinct entitlements.

## 8. Startup and restart reconstruction

The registry is rebuilt during startup warmup by replaying closed confirmation boundaries from the current trading day.

Warmup:

- calls the same confirmation authority used by live processing;
- rebuilds the same canonical entitlement keys;
- consumes previously observed entitlements;
- does not route historical orders.

This prevents an intraday EA restart from trading an old divergence again.

## 9. Trading-day boundary

The in-memory registry resets when the New York trading-day start changes. The entitlement key itself also includes the trading-day identity.

The reset cannot collide with an old signal because current-cycle and reference-cycle identities belong to the new trading day.

## 10. Capacity failure

If the one-shot registry reaches its configured capacity, the signal is rejected. It is never allowed through without deduplication.

```text
fail closed, never fail open
```

Default capacity remains controlled by `InpMaxSignalRegistryRecords`.

## 11. Audit contract

Accepted first observations include `trade_entitlement_key` in the main execution audit.

Repeated observations are written to a separate derived file:

```text
<main audit filename>_OneShot_Gate.csv
```

Default derived file:

```text
EXP0017_Phase14_Raw_Execution_Audit_V3_OneShot_Gate.csv
```

The gate audit records:

- observation close;
- entitlement key;
- source signal ID;
- CG and side;
- trading day;
- current and reference cycle starts;
- hunter and protected symbols;
- suppression state;
- reason.

## 12. Hard invariants

- No lower-timeframe candle timestamp may participate in entitlement identity.
- The entitlement must be consumed before planning and routing.
- A failed plan or failed order may not restore entitlement.
- Warmup may reconstruct state but may not send historical orders.
- Symbol order may not alter entitlement identity.
- Entry, stop, TP, volume, hedging, and visual settings may not alter entitlement identity.
- Duplicate suppression must be observable in logs or audit output.
