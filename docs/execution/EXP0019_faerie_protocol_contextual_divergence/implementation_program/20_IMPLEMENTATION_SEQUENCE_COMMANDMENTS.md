# Implementation Sequence Commandments

1. **Do not begin with the EA entry point.** Begin with contracts and the compatibility harness.
2. **Do not copy the legacy FP101 monolith.** Audit it for intent; rebuild through modules.
3. **Do not fork generic divergence truth.** Adapt stable cores or extract a generic primitive with regressions.
4. **Do not implement the indicator as a second detector.** It consumes `FP_Engine` snapshots/events.
5. **Do not put state in objects, labels, or colors.** Those are projections.
6. **Do not use ticks to order same-M1 sweeps.** M1 is canonical.
7. **Do not compress missing calendar days.** Missing is evidence.
8. **Do not confirm outside the owning session.** Strict session close is frozen.
9. **Do not hide suppressed signals in audit mode.** Suppression changes style and eligibility.
10. **Do not start execution before the complete indicator release.** Visual/replay parity is a hard gate.
11. **Do not hard-code FP-DEC-012.** Live quota consumption remains blocked.
12. **Do not stage unrelated files.** Every phase patch uses its own index.
13. **Do not claim compile/runtime success without logs.** Static, compile, tester, and forward evidence are distinct.
14. **Do not optimize before parity.** First prove exact full/incremental/restart behavior.
15. **Do not let product authority leak inward.** Core modules cannot import chart or trade entry points.
