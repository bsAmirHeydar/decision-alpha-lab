# EXP0013 — Astro Feature Meaning and Research Semantics

This document defines what each astrological raw field can become as a testable feature.

The project does not assume that astrology is causal. In Decision Alpha Lab, astrology is treated as a high-dimensional **time-state feature map**. A feature is useful only if it produces measurable distributional lift, sequence lift, or cluster density out-of-sample.

---

## 1. Longitude

Raw columns:

```text
*_lon
*_sign
*_sign_index
*_degree
```

Derived features:

```text
planet_sign
planet_element
planet_modality
planet_degree_zone
planet_ingress_window
```

Meaning:

Longitude is the cyclic angular location of a body on the ecliptic. For research, it tells us where the body is inside its 360-degree cycle. We do not trade the longitude itself; we test whether market outcomes are distributed differently when a signal occurs under a given angular state.

Example feature key:

```text
mars_sign=aries|mars_element=fire|mars_degree_zone=early
```

---

## 2. Latitude

Raw columns:

```text
*_lat
```

Derived features:

```text
planet_lat_zone
planet_lat_abs_bucket
```

Meaning:

Latitude measures distance north/south of the ecliptic. In research, this is a secondary geometry feature. It can be tested for path, volatility, and breakout distribution changes, but it should not be over-weighted until sample evidence exists.

---

## 3. Distance

Raw columns:

```text
*_dist
*_speed_dist
```

Derived features:

```text
planet_distance_bucket
planet_near_perigee_or_apogee_proxy
planet_distance_speed_state
```

Meaning:

Distance captures whether a body is relatively closer/farther in its cycle. For Moon this may be especially useful because it changes quickly. In the first version, distance should be bucketed and tested, not interpreted directly.

---

## 4. Longitude Speed

Raw columns:

```text
*_speed_lon
*_retro
```

Derived features:

```text
planet_speed_state = direct / retro / station
planet_retrograde
planet_station_window
```

Meaning:

Speed tells us whether a body is moving normally, retrograde, or nearly stationary. This is one of the strongest research feature families because station/retrograde states are rare and can define distinct time regimes.

Example:

```text
mercury_speed_state=retro
mars_speed_state=station
saturn_speed_state=direct
```

---

## 5. Declination

Raw columns:

```text
*_decl
```

Derived features:

```text
planet_decl_zone = north / south / equator / north_oob / south_oob
parallel / contra_parallel between bodies
```

Meaning:

Declination is a vertical sky coordinate. Out-of-bounds states are rare and should be tested as sparse filters. Parallel and contra-parallel can be treated as declination-based aspect equivalents.

---

## 6. Moon Phase

Raw columns:

```text
moon_phase_angle
moon_phase_bucket
moon_illumination_proxy
```

Derived features:

```text
moon_phase_bucket
moon_phase_half = waxing / waning / new / full
moon_illumination_bucket
```

Meaning:

Moon phase is a fast cyclic state. It is useful for testing whether a strategy's win/loss distribution, volatility response, or sequence behavior changes across the lunar cycle.

Important: the feature is not “buy on full moon.” The correct question is:

```text
Does this execution produce a different R distribution under this lunar phase bucket?
```

---

## 7. Aspects

Raw columns:

```text
*_angle
*_aspect
*_orb
*_applying
```

Derived features:

```text
aspect_name
aspect_class = fusion / tension / flow / none
orb_bucket = tight / close / wide / none
motion = applying / separating
```

Meaning:

Aspects are pairwise angular relationships. In Distribution Engineering, the important part is not the symbolic name; it is the conditional distribution attached to:

```text
pair + aspect_class + orb tightness + applying/separating
```

Example:

```text
mars_saturn_aspect_class=tension|mars_saturn_orb=tight|mars_saturn_motion=applying
```

## 8. Feature hierarchy

Use three levels of keys.

### Full raw key

Generated by Python and contains many conditions. Good for offline mining, dangerous for live gating because sample size can collapse.

### Research key

Generated by `DAL_AstroDF_BuildResearchKey`. Good for analysis and feature discovery.

### Compact execution key

Generated by `DAL_AstroDF_BuildCompactExecutionKey`. Good for connecting to Roulette/Jackpot gates because it preserves more sample size.

---

## 9. What can be used for entries?

Astro features should not be primary entry signals at first.

Professional use inside this project:

```text
Execution creates the signal.
Astro feature describes the time-state.
Distribution Engineering checks if that time-state improves cluster probability.
Roulette/Jackpot runs only when sequence lift is proven.
```

Allowed uses:

```text
filter entry permission
choose whether probe or full live is allowed
label trades for distribution mining
detect sequence-friendly regimes
```

Not allowed initially:

```text
enter buy/sell only because a planet is in a sign
optimize hundreds of astro combinations without OOS validation
use future candle data or future aspect completion as a current feature
```

---

## 10. Minimum validation standard

An astro feature is not accepted unless it improves at least one of these out-of-sample:

```text
P(win)
P(win after win)
P(win after 2 wins)
cluster count >= 3
cluster count >= 5
loss hazard after k wins
R distribution tail
```

The project title for this layer is:

```text
Astro Distribution Engineering
```

The core claim is not astrology. The core claim is that market executions can be conditioned by a deterministic external time-state map and evaluated with strict distributional statistics.
