# EXP0013 Astro Time Contract: No Second GMT Shift

The Python builder may generate a CSV using a broker GMT offset, for example `--broker-gmt-offset-hours 3`.

That means the CSV already contains two separate timestamps:

```text
broker_time = candle time in broker timezone, e.g. GMT+3
utc_time    = the UTC equivalent calculated by Python
```

MQL5 must not shift the candle time again.

Runtime lookup contract:

```text
chart candle open time == CSV broker_time
```

Therefore, if the chart candle is `2026.01.02 10:50`, MQL searches for `broker_time=2026.01.02 10:50` exactly. It does not subtract 3 hours. It does not add 3 hours.

The `utc_time` column is read from the CSV row and displayed as data generated by Python. It is not recalculated by MQL during lookup.

Default expert settings after this patch:

```text
InpBrokerGmtOffsetHours = 0.0
InpValidateUtcOffset = false
```

These inputs are now only for optional diagnostics. They are not part of lookup.

Use this when the CSV was generated with GMT+3:

```text
InpAstroCsvFile = astro_GMT3_M1_2026_to_now_mql.csv
InpBrokerGmtOffsetHours = 0
InpValidateUtcOffset = false
```

This avoids the mistaken double shift.
