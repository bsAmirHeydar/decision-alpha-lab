# Astro Professionalization Gap Map

This document lists the remaining distance between the current EXP0013 astro stack and a more professional pure-astrology / financial-astrology research platform.

It is intentionally doctrine-first.
Nothing here permits price contamination or market-indicator contamination.

## 1. What is already strong

- deterministic candle-aligned astro CSV builder
- transit, natal, aspect, declination, house, sect, benefic/malefic, and timing stack
- macro -> meso -> micro -> minute doctrine
- paper-first astro execution families
- final pure-astro gate and validation/export tooling

## 2. Main remaining gaps

### A. Raw doctrine completeness

These layers are either missing or only partially explicit in the current raw map:

- essential dignity is now explicit, but deeper traditional dignity layers are still missing
- dispositorship is now explicit, but multi-step chain interpretation is still early
- ingress intensity and station intensity are now explicit, but family-specific meanings can still sharpen
- solar-quarter timing is now explicit, but not yet split into richer seasonal doctrine variants
- eclipse proximity is now explicit, but eclipse-family timing doctrine is still early
- nodal timing context is present through node positions, but not yet elevated into doctrine-ready row fields

### B. Professional astrology doctrine depth

These are still incomplete relative to a very advanced astrology workflow:

- deeper mutual reception semantics
- triplicity / bounds / decans
- antiscia / contra-antiscia
- translated / collected light style logic
- perfected life/timing systems beyond the current natal starter layer
- sharper company / inception chart doctrine for traded instruments

### C. Financial-astrology specialization

The current stack is astro-native, but not yet fully specialized for financial-astrology schools:

- solar-quarter and cardinal gate timing should be explicit
- eclipse / nodal activation should become a first-class transition regime
- ingress/station clustering should be more visible in the final doctrine
- reference-chart doctrine should be stronger for inception-based assets
- family variants should distinguish slower macro-cycle doctrine from fast lunar trigger doctrine

### D. Operational professionalism

- dashboard should expose the new doctrine layers cleanly
- docs should state which layers are canonical, provisional, or still experimental
- validation reports should summarize new eclipse / quarter / dignity / dispositorship states

## 3. Current implementation order

### Phase 1 - now

- export explicit dignity, dispositorship, station intensity, ingress intensity
- export solar-quarter and eclipse-proximity row fields
- wire the new fields into MQL runtime types and CSV reader
- feed the strongest low-risk parts into doctrine context and timing logic

### Phase 2

- add richer reception and rulership-chain semantics
- expand natal/inception doctrine
- strengthen dashboard surfacing

### Phase 3

- add deeper traditional timing layers where they can remain deterministic and causal
- split doctrine profiles by family and market/reference-chart use

## 4. Purity rule

Even when inspired by financial astrology, geocosmic timing, or Gann-style time emphasis, this project keeps one hard rule:

- no price-derived feature may enter the astro signal engine
- no market structure may be smuggled into astro doctrine
- every astro field must be knowable at candle open

## 5. Important note on Gann

This project may borrow timing emphases that overlap with Gann-style work, such as cardinal gates, quarter turns, and cycle pressure.

It does **not** claim that a modern reconstruction of Gann is exact or complete.
Any such layer is treated as a doctrine hypothesis that must remain explicit, causal, and testable.
