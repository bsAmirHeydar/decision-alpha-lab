# Context as Movement Constraint

A context is useful only if it creates a movement constraint, a probable reversal area, or a boundary whose failure creates information.

The project should not trade context directly. It should convert context into a risk contract.

```text
Context -> Constraint -> Zone Candidate -> Risk Contract
```

## Examples

- Hook creates a near-death zone and stop behind hook.
- F1 creates a directional continuation area and stop behind the F1 waist.
- F2 creates reversal potential but may require lower-timeframe refinement.
- F3 creates broad potential but is too open for direct parent-timeframe execution.
