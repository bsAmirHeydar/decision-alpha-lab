# UI-REFORM-V9 — Alpha Lens Mobile Design Document

## 1. هدف سند

این سند، مبنای طراحی نسخه v9 اپ **Alpha Lens Mobile** است. هدف v9 این نیست که اپ فقط زیباتر شود؛ هدف این است که UI با فلسفه معاملاتی پروژه هم‌راستا شود:

> Alpha Lens باید یک **Quiet Premium Decision Cockpit** باشد؛ نه پنل سیگنال‌دهی، نه داشبورد نئونی شلوغ، نه فرم اداری.

اپ باید در لحظه فشار بازار، ذهن را منظم کند. هر بخش باید به یک تصمیم کمک کند:

```text
Context → Lens → Timeframe → Cell Bias → Risk → Reward → Action → Note
```

## 3. مشکل‌های نسخه‌های قبلی

### 3.1. نئون بیش از حد

در نسخه v8 تقریباً همه چیز glow داشت. این باعث می‌شد اهمیت نسبی اجزا مشخص نباشد.

اصلاح v9:

- نئون به hairline glow تبدیل شد.
- glow فقط feedback ظریف است، نه عنصر تزئینی غالب.
- shadowها کم شدند.
- active cell و focus state هنوز دیده می‌شوند، اما چشم را خسته نمی‌کنند.

### 3.2. پس‌زمینه زیادی فعال

دات‌گرید و خطوط نموداری در نسخه قبل زیادی دیده می‌شدند.

اصلاح v9:

- opacity دات‌ها و چارت‌ها پایین‌تر آمد.
- انیمیشن پس‌زمینه کندتر شد.
- خطوط نموداری به texture محو تبدیل شدند.
- اپ دیگر حس “crypto neon dashboard” ندارد.

### 3.3. متن‌ها بزرگ و سنگین

فارسی با weight بالا و اندازه زیاد سریع زمخت می‌شود.

اصلاح v9:

- فونت‌ها کوچک‌تر شدند.
- وزن‌ها از 900 به محدوده 560 تا 850 کاهش یافت.
- تیتر اصلی کوچک‌تر شد.
- متن کارت‌ها و راهنماها ریزتر و آرام‌تر شدند.

### 3.4. فرم‌ها زیاد select-heavy بودند

Selectهای native مخصوصاً در موبایل و دارک مود حس خام و غیر premium می‌دهند.

اصلاح v9:

- انتخاب‌های سلول به segmented controls تبدیل شدند:
  - جهت سلول
  - ریسک
  - ریوارد
  - وضعیت
- selectها فقط برای meta/final باقی ماندند.

## 10. Cell Bias

### 10.1. چرا Cell Bias لازم است؟

چون یک لنز و نتیجه آن لزوماً هم‌جهت نیستند.

مثال:

```text
Lens: هوک صعودی
Cell Bias: نزولی
```

معنی:

```text
ساختار از جنس هوک صعودی دیده می‌شود،
اما برداشت فعلی این است که این هوک ضعیف، failed یا ضدسناریو است.
```

### 10.2. وضعیت‌ها

| وضعیت | معنی |
|---|---|
| صعودی | از این لنز، خروجی به سمت بالا دیده می‌شود |
| نزولی | از این لنز، خروجی به سمت پایین دیده می‌شود |
| دوطرفه | conflict یا هر دو سناریو فعال است |
| خنثی | هنوز جمع‌بندی وجود ندارد |

### 10.3. اهمیت دوطرفه

`دوطرفه` برای بازارهایی که در decision zone هستند حیاتی است. این حالت به معنی no-trade قطعی نیست؛ یعنی هنوز نیاز به refinement یا child zone وجود دارد.

## 11. Risk

### 11.1. تعریف

Risk در این اپ فقط distance to stop نیست. Risk یعنی هزینه غلط بودن این نگاه.

### 11.2. وضعیت‌ها

| وضعیت | معنی |
|---|---|
| کم | stop واضح، زون فشرده، ابطال ارزان |
| متوسط | قابل قبول، اما نه ایده‌آل |
| زیاد | زون پهن، ابطال مبهم، هزینه خطا بالا |

### 11.3. قاعده ذهنی

```text
Risk کم یعنی اگر غلط شوم، ارزان غلط می‌شوم.
```

---

## 12. Reward

### 12.1. تعریف

Reward یعنی فضای باز شدن حرکت در صورت درست بودن نگاه.

### 12.2. وضعیت‌ها

| وضعیت | معنی |
|---|---|
| کم | فضای حرکت محدود |
| متوسط | فرصت قابل قبول |
| زیاد | نسبت حرکت به ریسک خوب |
| باز | امکان رشد، extension یا tail وجود دارد |

### 12.3. قاعده ذهنی

```text
Reward باز یعنی این فقط تارگت کوتاه نیست؛ ممکن است سود رشد کند.
```

## 13. Action

### 13.1. تعریف

Action تصمیم عملی همان سلول است.

### 13.2. وضعیت‌ها

| وضعیت | معنی |
|---|---|
| خالی | هنوز نظری ثبت نشده |
| رصد | مهم است اما هنوز اقدام نیست |
| Child | parent خوب است اما ورود دقیق‌تر لازم دارد |
| لیمیت | امکان گذاشتن limit قابل دفاع است |
| مدیریت | معامله فعال است و باید مدیریت شود |
| رد | این خانه ارزش اقدام ندارد |

### 13.3. تفاوت رصد و Child

`رصد` یعنی فقط نگاه کن.

`Child` یعنی ایده وجود دارد، اما ورود مستقیم هنوز گران یا خام است.

## 22. Use Case روزانه

### 22.1. روش استفاده سریع

1. نماد و بازه را تنظیم کن.
2. کانتکست را در یک جمله بنویس.
3. 1H را ببین.
4. اگر parent مهم بود، به 10M برو.
5. اگر child یا entry لازم بود، به 1M برو.
6. برای هر خانه فقط جهت، ریسک، ریوارد و اکشن را مشخص کن.
7. تصمیم نهایی را پایین ثبت کن.
8. اگر لازم بود اسنپ بگیر.

### 22.2. مثال

```text
1H / هوک صعودی:
جهت: دوطرفه
ریسک: متوسط
ریوارد: باز
وضعیت: Child

نتیجه:
Parent مهم است، اما ورود مستقیم ندارم. باید در 10M یا 1M child پیدا کنم.
```

## 26. حکم نهایی

Alpha Lens باید مثل یک دفتر تصمیم‌گیری دیجیتال لوکس باشد:

```text
کم‌حرف
دقیق
سریع
زیبا
آرام
قابل استفاده در لحظه بازار
```

هدف UI این نیست که کاربر را هیجان‌زده کند. هدف این است که قبل از معامله، ذهن را مجبور کند این سؤال‌ها را جواب بدهد:

```text
از کدام لنز نگاه می‌کنم؟
در کدام تایم‌فریم هستم؟
برداشت جهتی من چیست؟
هزینه خطا چقدر است؟
پتانسیل ریوارد چقدر باز است؟
الان باید رصد کنم، صبر کنم، لیمیت بگذارم، مدیریت کنم یا رد کنم؟
```
